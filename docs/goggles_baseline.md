# 护目镜第一版实施方案

状态：任务契约待补齐，尚未建立正式训练配置、数据版本或模型指标。当前目标为静态头部裁剪头像中的护目镜佩戴识别，详见[需求](goggles_requirements.md)。

## 实施顺序

1. 明确是否输出位置框、佩戴类别与疑难样本规则。
2. 核查护目镜数据的来源、许可、真实标签和头像完整性，确定需要时的裁剪规则。
3. 按原图/人物/序列分组，冻结独立划分、数据指纹及人工质量记录。
4. 依据输出选择分类或检测模型、初始权重与初始参数，形成可查看的显式配置，不继承未经验证的默认设置。
5. 完成准备、核查、训练、预测和评价的任务适配；合成样本回归只能验证程序逻辑。
6. 用户推进后先验证实际运行流程，再开展正式实验；根据验证集选择方案，最后评价冻结测试集。
7. 保存可复现模型、成功/失败图片、参数、指标和限制，按验收清单核对后上传。

## 两种输出对应的方案

| 输出要求 | 需要的数据与评价 |
| --- | --- |
| 每张头像仅给佩戴状态 | 头像级状态标签；分类模型；混淆矩阵、Accuracy及各类Precision/Recall/F1 |
| 还必须给位置框 | 明确框语义、状态标签及未佩戴表达；检测模型；框匹配、Precision/Recall及mAP |

两条路线尚未选定，不为此预先增加通用双模式实现。普通眼镜不自动视为护目镜，不确定状态不能强行标记为未佩戴；具体规则以课程要求和实际核查为准。

已完成通用基础代码和[显式头像裁剪工具](head_crops.md)，153项回归及合成CLI示例通过。真实数据处理、训练、模型评价与新依赖安装本轮未运行；数值参数与效果门槛不提前编造。用户最新授权本轮完成后上传，当前发布头像数据准备版，不视为完整模型验收。实验结果仍使用[记录模板](experiment_record.md)。
