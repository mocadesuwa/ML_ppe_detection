# 第四轮：部分微调与本机拖拽测试页

日期：2026-10-24，北京时间。用户明确要求自行训练和调整模型，并补充要求拖入新图片即可返回判断的前端页面。本轮在原272张v3数据上做两组预先限定的部分微调；不使用已封存的29张和24张测试调参。配置、父检查点和旧证据SHA见[训练前协议](goggles_finetuning_protocol.json)。

## 模型调整

此前模型只训练分类头，整个MobileNetV3 Small特征提取部分保持ImageNet状态。本轮从已验证的v2_control最佳任务检查点开始，分别解冻最后2个和最后4个特征模块，允许特征适应当前头像任务；其余前部仍冻结，所有特征BatchNorm运行统计保持不变。参考[PyTorch迁移学习说明](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)。

| 项目 | 固定设置 |
| --- | --- |
| 初始化 | v2_control最佳检查点，SHA `c66432ef67e71efb9341c7aceed7a2291e1f45cf4de313548ad3d9a03c6be8d7` |
| 候选 | tail2、tail4，仅解冻深度不同 |
| 分类头/尾部学习率 | 0.0001 / 0.00003，AdamW，weight_decay0.0001 |
| 梯度裁剪 | 范数上限1.0，遇非有限梯度报错 |
| 数据/输入 | 原train201、val47，224等比例填充，原温和增强 |
| 抽样/损失 | 原shuffle与训练频数倒数类别权重 |
| 次数 | seed42；先最深尾部2轮短跑26次更新，再两组各最多20轮、patience5 |
| 判定 | 固定argmax，无阈值搜索 |

短跑必须证实冻结前部不变、解冻尾部和分类头均真实更新、BatchNorm缓冲区不变、损失/梯度有限且最佳权重重载一致。完整运行继续核对数据、初始化检查点及其记录SHA。CPU计算线程限制为2以减少小批量图像变换的线程开销，不改输入、标签或抽样次数。

预检仍为eval/inference_mode，零更新、不构造优化器，仅在训练头像上前向。新预检额外绑定父检查点、父运行记录及解冻模块数；旧头部训练默认路径和旧检查点保持兼容。

`frozen_features_unchanged`继续表示整个特征提取部分是否完全不变：微调时它应为false，不伪造“整个骨干冻结”。新记录另要求`frozen_feature_prefix_unchanged`、`trainable_features_updated`及`feature_buffers_unchanged`均为true，预测/评价入口才接受这种已完成的模型。

## 选择与结果边界

候选验证macro-F1必须严格超过原0.849359，且佩戴Recall不低于原66.67%，才有资格入选；合格者依次按macro-F1、佩戴Recall、Accuracy、预定候选顺序选择。否则继续保留control。不追加随机种子、参数或阈值试验。即使验证提高，没有新独立保留集也不能宣称测试准确率提高。

## 拖拽测试页

页面和Python推理服务仅在本机运行，使用原生HTML/CSS/JavaScript，不增加前端构建依赖。上传单人头部裁剪头像后显示佩戴判断、两类分数、图像尺寸及耗时；可切换基线与完成验证的微调实验模型。原图在内存中处理，不向外部服务上传，不自动加入训练数据。

页面必须明确输入要求与“分数未经概率校准”。字节或RGB像素命中当前模型已登记头像时提示对应集合；未命中只能说明没有完全重复记录，不能保证来源独立。接口限制静态图片类型、上传大小、图像像素和本机同源访问，静态服务不暴露数据、权重或项目目录。
