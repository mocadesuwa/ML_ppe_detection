# 护目镜头像数据处理方案与实际结果

日期：2026-10-22，北京时间。用户已确认头像二分类、只输出状态。本页保留第一轮v2数据处理和训练前阶段记录，数据、标签、裁剪和划分保持本页版本不变。第一轮结果见[原训练报告](goggles_training_report.md)；当前另建272张v3数据的第二轮改进，见[新方案](goggles_improvement_plan.md)和[实际比较](goggles_improvement_report.md)。

## 完成条件与任务契约

保留原件及来源证据；每个候选都有保留/排除决定；头像、业务标签、来源组与原图可追溯；固定划分没有已知来源组交叉；分类目录、模型配置、依赖和真实训练批次通过检查；训练更新数为0。机器摘要见[训练前状态](pretraining_status.json)。

| 类别/状态 | 规则 |
| --- | --- |
| `not_wearing_goggles`，ID 0 | 眼部可判断且未正确佩戴防护镜；包括普通眼镜、太阳镜、额头/头顶佩戴 |
| `wearing_goggles`，ID 1 | 外观可辨识的防护镜正确覆盖眼部，包括包覆式安全防护眼镜、封闭式护目镜；不能据图片认证防护等级 |
| 排除，不进入模型类别 | 类型不明、眼部不可见/遮挡、严重模糊、头部框不合格或混入其他头部；不强行标为未佩戴 |

标签按单个头像确定，不按整图是否出现护目镜赋值。类别ID按ImageFolder字母顺序固定；无需护目镜位置标注。实际逐项决定由Codex视觉复核，未进行第二标注者一致性评估，不能称为专家双人审核。

## 来源与清洗

1. 保留已有PPEs v7的100张原图，复核全部146个原眼部对象；原`goggles`不是业务真值。
2. 用户允许少量补充，总规模约200张。新增SH17作者Kaggle版本1的80张原图和VOC原标注，共180张原图、226个候选对象；SH17原图126,815,719字节，PPEs原图13,696,425字节。未下载完整数据包。
3. 第三方SH17镜像仅定位候选。其数字类别与作者顺序不一致：先用18份作者VOC逐框对照，确认实际所需映射（镜像类别5为head、16为glasses），再为每张补充图下载作者原图和VOC，核对头部框。未使用640×640拉伸镜像图片。许可按作者CC BY-NC-SA 4.0记录，不采用镜像较宽松的声明。
4. 每张原图和原标注计算SHA256，PPEs下载另核对ZIP成员CRC32。以原生像素判断，不增强模糊图片、不覆盖原件。
5. 初筛198张头像；实际打开全部198张试裁剪后，再排除7张混入其他头部或眼部仍不清楚的样本。最终191张：未佩戴145、佩戴46；排除35个对象，原因逐项留存。

PPEs的68个原`goggles`对象变为32佩戴、23未佩戴、13排除；78个原`no_goggles`对象变为65未佩戴、13排除。SH17最终71张：未佩戴57、佩戴14；排除9张。原始标签均保留，未改写原标注。

来源证据见[原100张记录](data_sources/ppes_v7_review_100_20261022.json)、[SH17原图记录](data_sources/sh17_original_80_20261022.json)、[最终逐项复核](data_sources/goggles_v2_review.json)。[初筛复核](data_sources/goggles_v1_review.json)和[试裁剪清单](data_sources/goggles_v1_head_plan.json)只作过程证据。

## 头像裁剪与像素核查

- PPEs从原眼部框`[x,y,w,h]`提出头部框`[floor(x-.25w), floor(y-.9w), ceil(x+1.25w), ceil(y+1.05w)]`，限制于图内后逐张视觉复核；它是本轮显式框来源，不是头部检测模型。
- SH17使用作者原始VOC头部框，各方向扩5%，限制于图内并实际查看。不按第三方镜像比例拉伸原图。
- 保留可用的额头、眼部、眼镜和下巴；少量原图头发/帽沿边缘截断可接受，眼部丢失、混入另一人头部或无法判断的剔除。最小头像短边64像素；PPEs原眼部框至少48×24。最终最小原生头像为78×102，放大不能恢复细节。
- 保存原生分辨率RGB PNG，不离线增强、不在数据目录中预先缩放。`prepare_head_crops`保留原图/输出哈希、来源组、框和标签；`check_head_crops`逐像素核对。
- 最终191张的像素与已查看的试裁剪保留项完全一致。文件完整性通过，与视觉语义判断分别记录。

最终清单为[头像框v2](data_sources/goggles_v2_head_plan.json)，质量记录为[精确指纹绑定的复核](data_sources/goggles_v2_quality_review.json)。

## 来源组、重复与固定划分

PPEs的全部工厂帧保守合为一个来源组，不以日期、机位或连续帧拆成不同集合。SH17按实际查看的场景系列合组，邻近来源编号也保守合并；已识别的相同木工、实验室、电子工作坊等系列保持同组。共65个显式来源组。未使用人脸识别或嵌入，缺失的摄影者/身份关系仍无法完全保证。

先用固定种子42、目标比例70/15/15生成整组计划，再在任何模型评价前调整来源覆盖：初始计划把SH17全部正例留在验证/测试，容易混淆来源与类别；将实验室系列572和木工系列679整组换入训练，并把等量的训练负类组换出。保留集合大小和来源组边界；调整记录存在本地最终划分清单中，不根据模型结果挑选样本。

完全重复头像和相同原图由既有分组工具传递合并，标签冲突会拒绝。整图前轮831对相似候选全部受PPEs同组约束；本轮头像在不同显式组之间按dHash≤3或pHash≤6筛查，候选0。该阈值检查不能证明没有同人或所有近重复。最终显式来源组跨集合为0，dry-run与初始发布分组一致；来源覆盖调整另明确记录。测试集随后冻结，不用于反复选方案。

## 训练格式与防止静默错误

正式本地目录为`dataset/goggles/classification_v2_20261022/`：

```text
classification_v2_20261022/
  train/not_wearing_goggles/*.png
  train/wearing_goggles/*.png
  val/not_wearing_goggles/*.png
  val/wearing_goggles/*.png
  test/not_wearing_goggles/*.png
  test/wearing_goggles/*.png
  manifest.json
  quality_review.json
```

导出保留头像字节，要求全部显式标签、完整视觉/来源组复核和相符指纹；核查遗漏/额外文件、重复像素跨集合、类别映射、原图/头像变化和审核附件哈希。两种来源的两类均须在训练中出现。输出不覆盖旧目录，先核查临时目录再发布。

数据指纹为`b9176dd923d011a63f7373e126d0997f9959c2e324debc20117140013250e7af`。原图、头像、划分、标签和复核记录发生变化后，应建立新版本，不能沿用当前预检。

## 模型输入与训练计划

[当前配置](../configs/goggles_classification_v1.yaml)选择Torchvision MobileNetV3 Small的ImageNet初始权重，另换未训练的两类头。官方权重约10.3 MB，本地完整SHA256及发布文件名哈希前缀见[来源记录](initial_classification_weights.json)，不是护目镜训练模型。模型接口参考[Torchvision官方文档](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html)。

- 模型输入224×224：等比例缩放并填充，保留整张头像，不中心裁剪或随机裁掉眼部；ImageNet均值`[.485,.456,.406]`和标准差`[.229,.224,.225]`。
- 只在未来训练加载时使用0.5概率水平翻转和轻微亮度/对比度/饱和度变化；验证、测试不增强，未生成离线增强副本。
- 首版计划冻结特征骨干及其BatchNorm，仅训练分类头；AdamW、学习率0.0003、weight decay 0.0001、batch 16、最多30轮、验证macro-F1选最佳、patience 8、workers 0、种子42。这是待实测初始参数，不称最优方案。
- 类别权重只由训练频数计算：未佩戴0.685567、佩戴1.847222；不使用验证/测试频数决定权重，不复制负类或增强评价集。

## 本轮实际训练前验证

已有项目虚拟环境可用，未安装依赖：Python 3.14、PyTorch 2.11.0+cu128、Torchvision 0.26.0+cu128、Pillow 12.3.0；RTX 3060 Laptop GPU 6 GB的CUDA运算通过。实际预检使用训练集两类的16张头像，检查加载、训练专用增强和输入张量，并在`eval`、`inference_mode`下前向：16×3×224×224→16×2，GPU峰值已分配约54.72 MiB；参数和缓冲区不变，未构建优化器、无反向传播、梯度更新0。未在验证/测试图上做模型前向。

训练前阶段189项累计回归通过，分类CLI的真实`--dry-run`和当时预检绑定门禁通过；该阶段没有执行`--start`，未验证拟合、反向显存、更新、早停或检查点，不提供模型指标。这是前阶段快照；后续已按用户授权执行显式训练，匹配预检、203项回归与真实模型结果见[训练流程](classification_training_workflow.md)及[训练状态](training_status.json)。

每个评价集仅5个正例，且当前主要是工业监控和公开素材，不能据此认定实验室部署效果。后续训练使用原冻结划分，以验证集选择最佳，方案确定后才评价测试；不会根据测试结果改标签、来源组或超参数。
