# 本机拖拽识别页

2026-10-28增加图形启动器，并完善中文识别工作台。界面仍在浏览器中运行，复用原有本机推理接口、Python环境和模型。训练曲线等辅助资料继续默认收起；本轮没有训练、数据处理、模型调整或封存测试评价。

在项目目录双击 **`护目镜识别.lnk`**。图形启动器就绪后会自动打开`http://127.0.0.1:8765`，无需保留CMD窗口。启动器提供“打开识别页面”“停止服务/重新启动”和“查看运行日志”；关闭启动器会停止它创建的服务。重复点击快捷入口会返回已有启动器。

快捷方式包含本机绝对路径，因此不进入Git。当前机器已生成；重新克隆或移动项目后，在项目目录执行一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/create_frontend_shortcut.ps1
```

此命令只重建项目根目录快捷方式，不更改系统执行策略，不安装依赖。也可手动运行图形启动器：

```powershell
.venv/Scripts/pythonw.exe -X utf8 -m scripts.launch_frontend
```

保留原命令行入口作为备用：

```powershell
.\start_demo.cmd
```

使用备用CMD入口时，保持其服务窗口运行，关闭时按`Ctrl+C`。端口被占用时先关闭此前启动的服务；图形启动器不会终止不属于它的进程，也不会自动占用其他端口。手动入口可按下方命令改端口。不要直接双击`web/dist/index.html`，页面需要Python推理接口。

启动日志保存于`.cache/frontend-launcher.log`。缺少环境或模型时显示错误，服务启动超过60秒时停止本次尝试；修复后可点“重新启动”。默认仍请求GPU0，不自动回退CPU。

## 操作

打开页面即可上传头像并查看识别结果。工作区下方的“训练曲线”“实验对照”“数据与规则”是辅助资料按钮，默认全部收起；点击展开，再点收起，切换按钮会关闭上一个面板。资料操作会保留当前头像与识别结果。

1. 将一张**单人头部裁剪头像**拖入左侧，或点“选择图片”。保留完整眼部；多人、全身图片需先自行裁剪。
2. 默认使用当前基线。点“开始识别”，右侧显示佩戴/未佩戴判断、两类分数、图像尺寸、本次推理耗时及实际设备（如`cuda:0`）。首次识别包含模型加载，会稍慢。
3. 可以更换或清空图片、切换微调实验模型，并下载本次判断JSON。图片保留完整画面，显示文件名、尺寸与大小；预览读取完成后才能识别。微调模型只供比较，没有优于基线，不默认替换。

服务停止或连接中断时，上传区和结果区会显示中文恢复提示，顶部标明“连接中断”并提供“重新连接”。在启动器中重新启动服务后，原页面可保留已选图片直接重试；初次连接失败时先点“重新连接”读取模型。图片格式/尺寸等业务错误保留原原因，不误报网络中断。切换模型、更换或清空图片会清除不再对应的旧判断与下载。

需要查看模型记录时，点“训练曲线”可切换四个实验以及验证macro-F1/训练与验证损失；点“实验对照”查看同一47张验证集的比较；点“数据与规则”查看冻结划分、基线指标、历史24张测试与判断规则。这些资料仅读取已保存记录，不重新训练或测试。

支持静态JPG、PNG、BMP、WebP，单张不超过8MiB，至少16×16，总像素不超过1600万。动图、损坏文件和超限图片会提示错误。分数未经概率校准，不能视为真实正确率。输入不符合头像要求时仍可能输出二分类结果，本模型没有自动判断“非头像/无法判断”的第三类。

佩戴规则为防护镜正确覆盖眼部；普通眼镜、太阳镜或额头佩戴归为未佩戴。看不清的图片不适合评价模型效果。

## 模型与数据

- 当前默认：`results/classification/goggles_v2_control/best.pt`。
- 可选实验：`results/classification/goggles_v4_tail4/best.pt`，验证macro-F1与基线同为0.8494；无新的独立测试。详细训练比较见[第四轮报告](goggles_finetuning_report.md)。
- 输入图片在本机内存中读取，不写入上传目录、不向外部服务发送、不自动加入训练集。只有主动点击下载时，浏览器才保存判断JSON。
- 与当前模型登记的train/val/test头像在文件字节或RGB像素上完全相同时，页面提示所属集合。这里只读取清单哈希，不主动预测任何测试集。未命中不代表已经证明是独立来源；也不能识别“同一人换了一张照片”。
- 页面可接收模型未见过的新图片，但模型训练的泛化能力仍受小样本限制。建议使用清晰、独立拍摄的新头像逐张观察。

本地虚拟环境、真实数据和权重没有上传Git。另一台电脑仅克隆代码后不能直接识别，需自行准备相同依赖及本地有效检查点；程序不会自动下载权重、自动训练或改变数据。

## 命令与接口

无需新依赖。前端是原生HTML/CSS/JavaScript，图形启动器使用现有Python自带的Tkinter和Windows快捷方式；后端继续使用Python标准库HTTP服务、现有Pillow和PyTorch。手动启动示例：

```powershell
.venv/Scripts/python.exe -X utf8 -m src.serve_demo --weights results/classification/goggles_v2_control/best.pt --candidate results/classification/goggles_v4_tail4/best.pt --device 0 --port 8765 --open-browser
```

只使用基线时去掉`--candidate`。默认使用GPU设备0，不静默回退CPU；确需CPU时可显式改为`--device cpu`。服务仅监听`127.0.0.1`，只允许本机同源请求；静态路由只开放前端资源及聚合训练摘要，不开放数据、权重或项目目录。

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `GET /api/models` | 无 | 可选模型ID、名称、说明及上传上限 |
| `POST /api/predict` | 原始图片二进制body，`X-Model-Id: baseline`或`candidate` | `label`、`probabilities`、尺寸、耗时、图像/权重SHA及`known_splits` |

请求采用图片原始字节，不使用multipart。类别为`not_wearing_goggles`/`wearing_goggles`，没有位置框。服务启动时核对完整训练记录和权重SHA，首次推理核对检查点契约；运行中模型/记录变化将要求重启。
