# 护目镜数据选择与核查

更新日期：2026-10-14。当前未确认护目镜数据来源、版本或样本规模，本轮未下载、导入、裁剪或重标注真实数据。

## 选择条件

- 确认原始发布入口、版本、许可及允许的课程用途，保存来源与压缩包哈希。
- 实际查看护目镜佩戴和未佩戴样本，明确普通眼镜、额头佩戴、侧脸与遮挡的标注规则。
- 确认标签对应当前头像中的人；不能因整图出现护目镜就标记所有头像为佩戴。
- 若采用分类，需可靠的头像级状态标签；若采用检测，需明确框语义与未佩戴状态的表达。当前两条路线均待确认。
- 图像与标签必须可追溯。缺失许可、类别含义不明或只有预测结果的数据，不能作为已经核查的训练真值。

## 头像与划分

直接使用已裁剪头像时检查头部及眼部区域是否完整、是否混入他人、尺寸与可判断性是否足够。需要裁剪时先确定规则，保存原图、裁剪区域、标签和排除原因，不覆盖原件。

已有[显式头像准备工具](head_crops.md)可在规则明确后使用；它仅执行给定框，不判断头部是否合理，不自动生成佩戴标签。`crops_manifest.json`绑定原图和输出哈希、框与来源组；裁剪完成状态不能替代人工核查或训练前就绪。

同图裁剪、同人、同序列及近重复样本按来源分组后划分；记录来源缺失的限制。测试集在方案确定后用于最终评价，不用于反复选参。

现有`src.check_head_crops`会只读核对裁剪的哈希、尺寸、像素及目录完整性，不判断佩戴状态。`src.split_head_crops`在显式标签完整时可建立划分计划，合并同源和完全相同头像，保存输入指纹与实际计数；不能自动发现同人、序列和近重复。真实数据的人工质量记录和模型格式仍未建立，命令与限制见[头像准备接口](head_crops.md)。
