## 本轮实际核查与限制

- 100张均通过图片解码、尺寸、文件数量、每图SHA256及COCO引用检查；146个框均为有限、正尺寸、图内坐标，非法框0。
- 原始字节与解码RGB像素的完全重复组均为0。整图dHash距离≤8找到831对相似候选，可能受固定背景影响，不等于831对已确认重复，不据此自动删图或识别人。
- 146个眼部框中25个的短边小于32像素。它们是原眼部对象框，不是头部框；放大显示不能补回细节，裁剪最小尺寸规则仍待确认。
- 已查看三张正式分层抽查图，各层4张，共12张，编号、展示的对象ID见来源清单；另有早期12张临时预览，与正式抽查重叠3张，候选池合计查看21张。未逐张、逐对象完成人工审核，每张正式拼图最多展示两个眼部放大区域。
- ID 765、170、538标作goggles，但外观为细框眼镜，不能仅凭图确认属于防护护目镜。ID 715、5895可见疑似头顶/额头眼镜，原标签不同，列入佩戴位置疑难；不自动重标。
- 抽查为工厂固定机位；715、5895、3637画面有相近时间戳。图像数量不能代表独立人物或独立来源组，当前未建立人物/序列分组，也未证明跨实验室场景适用性。

因此状态为`raw_review_pool`、`target_labels_confirmed=false`、`training_ready=false`、`visual_review_completed=false`。完整性通过只证明文件和标注结构可用，不能证明护目镜语义、佩戴正确或人工质量审核通过。

## 选择条件

- 确认原始发布入口、版本、许可及允许的课程用途，保存来源与压缩包哈希。
- 实际查看护目镜佩戴和未佩戴样本，明确普通眼镜、额头佩戴、侧脸与遮挡的标注规则。
- 确认标签对应当前头像中的人；不能因整图出现护目镜就标记所有头像为佩戴。
- 若采用分类，需可靠的头像级状态标签；若采用检测，需明确框语义与未佩戴状态的表达。当前两条路线均待确认。
- 图像与标签必须可追溯。缺失许可、类别含义不明或只有预测结果的数据，不能作为已经核查的训练真值。

## 头像与划分

直接使用已裁剪头像时检查头部及眼部区域是否完整、是否混入他人、尺寸与可判断性是否足够。需要裁剪时先确定规则，保存原图、裁剪区域、标签和排除原因，不覆盖原件。

已有[显式头像准备工具](head_crops.md)可在规则明确后使用；它仅执行给定框，不判断头部是否合理，不自动生成佩戴标签。`crops_manifest.json`绑定原图和输出哈希、框与来源组；裁剪完成状态不能替代人工核查或训练前就绪。

同图裁剪、同人、同序列及近重复样本按来源分组后划分；记录来源缺失的限制。测试集在方案确定后用于最终评价，不用于反复选参。

现有`src.check_head_crops`会只读核对裁剪的哈希、尺寸、像素及目录完整性，不判断佩戴状态。`src.split_head_crops`在显式标签完整时可建立划分计划，合并同源和完全相同头像，保存输入指纹与实际计数；不能自动发现同人、序列和近重复。真实头像的全量人工质量记录和模型格式仍未建立，命令与限制见[头像准备接口](head_crops.md)。

## 首轮检索后的待办（后续已按处理方案推进）

1. 用样本明确普通眼镜、护目镜、额头佩戴与无法判断的规则，不强行把疑难样本标作未佩戴。
2. 核查来源与拍摄序列，筛除不适用样本；必要时优先补查上表小型备选。没有Goggles标注不等于已确认未佩戴。
3. 明确头像范围、最小尺寸及位置框语义，再给显式头部框并合并同图、同人、同序列和近重复来源组。
4. 后续才建立真实头像、业务标签及冻结划分，记录排除原因与数据版本。本轮不训练。

本地ZIP导入入口为`python -m src.import_data --help`，不联网；`src.source_review`只支持VOC，不能直接读取本次COCO JSON。本轮使用本地一次性脚本核查COCO和原图，没有扩展项目程序、裁剪真实头像或运行模型。
