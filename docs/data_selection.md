初始记录日期：2026-10-07；更新日期：2026-10-08。状态：已完成下载、全量结构检查及第一轮定向视觉抽查，尚未修正或固定划分。详细结果见[原始核查报告](data_reviews/2026-10-08-source-review.md)。

## 1. 建议优先检查的候选

[Face Mask Detection，Kaggle](https://www.kaggle.com/datasets/andrewmvd/face-mask-detection)。

使用该数据集开展实验的[原始研究论文，第 3.1 节](https://archive.ceciis.foi.hr/public/conferences/2022/Proceedings/IS/IS4.pdf)描述其原始数据为 853 张图片、三类状态、PASCAL VOC 格式的 bounding box：with_mask、without_mask、mask_weared_incorrect。

以上介绍最初来自实际使用该数据开展实验的论文。2026-10-08 通过 Edge 实际查看发布页，确认当前显示版本 1、三类 PASCAL VOC 标注和 CC0 许可标识；原下载 URL 未固定版本号，本轮没有重新下载。页面归属为 Make ML 的 Mask Dataset，原归属站点在本次访问时显示停放域名，未取得坐标细则。论文的模型结果不作为本项目结果，也不采用其先增强再划分的处理方式。

本轮全量检查：853 张图片可读取且 XML 尺寸一致，共 4,072 个目标；两种当前坐标约定均有 842 份通过、11 份失败，实际包含 12 个 xmax=401/图片宽=400 的框。旧报告每图只列首个错误，本轮补齐 603 的第二个框。另发现 5 组相同图片字节、框坐标不同的重复标注，以及当前 dHash 阈值漏掉的裁剪画面候选。未自动裁剪框、删除图片或改写 XML。

原始 ZIP 大小 416,968,083 字节，SHA-256 为 cabae358a60492a1b96da0510c31475414b64100480ae52cadbe00753bbef904。来源与哈希记录在 dataset/raw/face-mask-detection/source.json。

建议的标签映射：

| 原始 XML 标签 | 项目类别编号 | 项目名称 |
| --- | --- | --- |
| with_mask | 0 | mask |
| without_mask | 1 | no_mask |
| mask_weared_incorrect | 2 | mask_incorrect |

映射保留原始类别含义，原始字符串按文件内容核对，转换时不自动猜测未知标签。

为什么先检查它：任务集中于一种用品，规模适合安排第一轮实验，并已有矩形框标注。仍需确认三类框是否都采用人脸区域，以及不同图片中规则是否一致。

## 2. 多用品扩展候选

R2PPE 的作者论文：[An image dataset for surveillance of personal protective equipment adherence in healthcare](https://www.nature.com/articles/s41597-024-04355-0)。作者描述了 10,034 张图片、123,751 条标注，涉及口罩、隔离衣、护目用品和手套，以及不同佩戴状态。

它与多用品状态检测的方向相关，但医疗模拟场景不等同于实验室。视频抽帧数据还需要按视频或拍摄批次划分，避免相邻帧泄漏。规模、类别规则和数据处理工作量都高于单用品方案，建议在第一个 baseline 完成后再评估。

扩展时从作者论文的数据可用性说明进入原始数据发布记录，核对许可、格式、划分与样例；本次未下载该数据。

## 3. 哪些数据不能直接使用

- 仅按 with_mask / without_mask 文件夹分类、没有 bounding box 的人脸分类数据，不能直接作为完整图片的 YOLO 检测训练集。
- 只有用品实体框、没有未佩戴状态框的数据，可以训练用品检测，但不能据“没有报出用品”直接评价未佩戴状态检测。
- 别人已训练好的模型与预测图片，不能替代本项目的数据划分和真实实验。
- 来源、版本或类别映射不明的 YOLO 格式副本，需要先核实再采用。

## 4. 拿到数据后的操作顺序

1. 保存原始压缩包与来源记录，解压至 dataset/raw/，保留原始标注。
2. 清点图片和 XML 是否配对，检查文件可读性与实际图片尺寸。
3. 统计每个原始标签的目标数与含该类的图片数。含多个类别的图片会在多个类别统计中出现，不能把这些图片数相加当作总图数。
4. 画出至少 30 张原始标注样例，覆盖三类、小人脸、侧脸和多人图片，核对框范围与状态标签。
5. 检查重复与近重复图片；有来源信息时按来源分组，没有时记录分组与去重方法的限制。
6. 决定保留三类还是修改任务，将排除图片和原因写入清单。
7. 固定 train / val / test，保存清单，转换为 YOLO 格式，再可视化检查一次。
8. 写入 dataset.yaml，检查类别顺序与训练脚本读取结果一致。

## 5. XML 转 YOLO 时要核查什么

PASCAL VOC 常用 xmin、ymin、xmax、ymax 描述框，YOLO 使用归一化的中心与宽、高：

```text
x_center = ((xmin + xmax) / 2) / image_width
y_center = ((ymin + ymax) / 2) / image_height
width    = (xmax - xmin) / image_width
height   = (ymax - ymin) / image_height
```

这是连续坐标约定下的转换。实际 XML 的坐标可能采用从 1 开始或含右端点的规则，实施时必须核实数据约定，再统一转换到连续坐标，不能只机械套公式。

示例：图片 800×600，连续坐标框为 (200, 150, 400, 450)，类别为 0，则 YOLO 行为：

```text
0 0.375 0.5 0.25 0.5
```

这是教学示例，不是数据集中的真实样本。YOLO 格式依据：[Ultralytics 检测数据格式](https://docs.ultralytics.com/datasets/detect/)。
