# 护目镜佩戴识别需求

更新日期：2026-10-22（北京时间）。当前工作区仅围绕护目镜任务维护，历史日志保留其审计性质，不作为当前需求或实测成果。

## 已明确的要求

| 项目 | 要求 |
| --- | --- |
| 对象 | 仅识别护目镜佩戴情况 |
| 输入 | 静态图像，使用头部裁剪头像 |
| 首版范围 | 图片或图片目录，不增加视频、摄像头、身份识别或自动头部检测 |
| 实施方式 | 明确规则后分轮修改，代码简洁，每轮记录与验证 |
| 版本 | 用户最新要求本轮完善并验证后上传GitHub，发布头像数据准备版；保留独立提交和`v0.1.0` |
| 当前推进 | 自行检索并获取小规模相关数据集，先不训练；需要新增依赖时仅在项目虚拟环境安装 |

## 待确认与建议

用户目前要求把“是否必须输出位置框”列为待确认。因此分类/检测路线、模型、标注格式和最终指标尚未确定。

| 问题 | 需要明确的规则 |
| --- | --- |
| 输出形式 | 每张头像仅给状态，还是还需位置框 |
| 框语义 | 若需要框，是护目镜实体还是带状态的头部区域；未佩戴时如何表达 |
| 类别 | 建议先考虑佩戴/未佩戴两类，是否需要其他状态须依据题目与真实样本确定 |
| 佩戴定义 | 额头佩戴、普通眼镜/太阳镜、侧脸、遮挡和无法判断的情况如何处理 |
| 头像来源 | 已有裁剪图，还是从原图的已核查头部框派生；不默认增加头部检测模型 |
| 裁剪规则 | 主要头部、保留范围、扩边、最小尺寸及异常输入处理 |
| 课程细则 | 数据来源/许可、场景、规模、报告与指标门槛 |

二分类和裁剪参数均不是已经确认的题目要求。不确定样本先登记，不能强行标为未佩戴。

## 当前能力与待完善内容

- 已有显式输入的本地ZIP导入、通用源数据核查、标签/清单/指纹与分组划分检查，以及静态图片预测记录。
- 已新增显式头部框裁剪：保留原图、框、来源组、可选标签及哈希，支持无输出dry-run；接口约定见[头像准备](head_crops.md)。不自动决定具体头部保留范围。
- 已补齐只读头像完整性核查及显式标签的来源分组计划：对比原图区域像素、核对目录/指纹，合并同源和完全重复头像后固定划分，不生成模型专用格式或宣布人工核查完成。
- 当前训练、评价和预测保留检测后端，不代表护目镜最终模型路线已经选定。
- 测试使用临时合成数据和中性标签，不构成护目镜训练数据、模型或效果指标。
- 已获取100张PPEs v7候选原图及原标注并记录来源与哈希，详见[数据选择](data_selection.md)；它们仍是待复核原图，未生成真实头像、确认业务标签或冻结划分。
- 尚无训练就绪的护目镜真实数据版本、最终任务配置、训练结果或实测指标；头像裁剪、核查与划分程序仍仅用合成图像验证。

## 后续顺序与约束

1. 先用小规模候选原图核查来源、许可、版本与原标注；不依赖模型路线的检索和下载可先进行。
2. 用实际样本明确输出、类别及头像/裁剪规则，再建立对应的独立数据版本；原始`goggles`标签不直接等于已确认的护目镜真值。
3. 同一原图的所有裁剪、同一拍摄序列、已知同人与近重复样本保持在同一来源组，再划分train/val/test；来源无法核实时记录限制。
4. 裁剪绑定原图与区域。分类使用头像级标签；检测还需转换框坐标、检查边界与可见性。保留原件，不自动猜测标签。
5. 按最终任务调整准备、质量检查、配置、模型、预测/评价与报告，每轮代码修改后累计回归。
6. 依据验证集选择方案，最终确定后使用冻结测试集。训练、依赖安装和真实数据处理按用户明确推进执行。

只改文档时执行文档检查，不重复模型或数据测试；不把生成拼图当作完成人工核查。

## 第一版验收

- [ ] 输出类型、类别、需要时的框语义和头像规则明确，文档、配置与程序一致。
- [ ] 护目镜数据来源/许可、标签、分组、裁剪及实际质量核查可追溯。

- [ ] 异常与不确定输入有明确处理；空检测不直接当作确定未佩戴。
- [ ] 回归、真实入口及任务效果有实际证据，未运行的训练/评价明确标注。
- [ ] 方案、实验记录、当前说明、摘要和独立日志准确，上传前核对内容不含真实头像、缓存或权重。

当前属于基础代码阶段，不能把通用回归通过称为护目镜模型已完成。
