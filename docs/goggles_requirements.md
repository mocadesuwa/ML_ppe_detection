## 2. 待确认项与建议

**位置框要求仍待确认。** 用户本轮回复“暂时不清楚，先在需求文档中列为待确认”。因此暂不确定任务类型、模型、标注格式或最终指标。

| 问题 | 建议或可选方案 | 对后续工作的影响 |
| --- | --- | --- |
| 是否必须输出位置框？ | 只输出每张头像的状态可采用图像分类；必须定位则采用目标检测 | 决定模型任务、数据结构、预测结果和评价指标；实现前需明确 |
| 若要框，框住什么？ | 区分护目镜区域与带状态的头部区域 | 未佩戴时没有护目镜实体，不能随意制造“未佩戴护目镜框” |
| 分几类？ | 建议先考虑“佩戴 / 未佩戴”两类，暂拟 `with_goggles` / `without_goggles` | 尚未定稿，不继承口罩“错误佩戴”类 |
| 什么算佩戴？ | 明确额头佩戴、普通眼镜/太阳镜、侧脸、遮挡及不确定样本规则 | 先形成标注说明和示例，不确定样本先登记，不强行标为未佩戴 |
| 头像由谁裁剪？ | 使用已有头像，或依据已核查的头部框生成可追溯副本 | 不默认新增头部检测模型，不把旧口罩框当头部真值 |
| 裁剪标准？ | 建议一图一个主要头部；边界、扩边比例、最小尺寸及异常规则待定 | 防止切掉护目镜、混入他人眼部或破坏标签语义 |
| 数据与课程细则？ | 来源/许可、实验室场景占比、规模、报告格式与数值门槛待核对 | 不承诺尚无依据的样本数或准确率 |

“头部裁剪头像”是已明确的输入方向；一图一头、两类方案和裁剪参数是建议，不能写成已确认的题目原文。

## 4. 后续数据与裁剪约束

- 保留原图、原标签和旧口罩版本；护目镜数据、裁剪副本、划分、核查及实验使用独立版本，绑定来源和哈希。
- 同一原图的所有头像、同一拍摄序列、已知同人及近重复样本归为同一来源组，再固定 train/val/test；不能将同图的不同裁剪随机分到不同集合，无法核实的来源记录限制。
- 保留原图与头像的对应关系。检测时将标签框转换到裁剪坐标并检查边界和可见性；分类时使用头像级标签，不以整图“出现护目镜”直接标记所有头像。
- 实际查看佩戴、未佩戴及疑难样本，记录查看范围和排除项，不把程序生成拼图等同于已完成人工核查。
- 根据验证集调整方案；方案确定后使用冻结测试集作最终评价。

以上为后续实施要求，本轮未裁剪、重标注或划分。
