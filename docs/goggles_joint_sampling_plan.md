# 第三轮：类别与来源组联合均衡对照

日期：2026-10-23，北京时间。用户授权继续后续任务。本轮只增加一个训练候选，用验证结果判断能否改善佩戴漏判，保持当前v3数据、旧模型及两组已评价测试冻结。训练前固定的配置哈希、旧证据哈希及选择规则见[协议](goggles_joint_sampling_protocol.json)。

本方案现已执行完成，候选未入选，新来源未并入，详见[实际报告](goggles_joint_sampling_report.md)。下文保留本轮预先限定的实验设计。

## 原因与限定方案

上一轮仅按来源组均衡时，佩戴样本的期望抽样占比从21.89%降至约10.09%。本轮令每个类别的抽样总权重相同，再在每类内均分给来源组，最后均分给该类、该组中的图片：

`weight(image) = 1 / (该类包含的来源组数 × 该来源组中属于该类的图片数)`。

同一来源组可以同时含两类，分别计算各自权重。当前训练数据中，未佩戴覆盖65组、佩戴覆盖8组；联合抽样的期望类别占比各50%，工厂组每轮期望约14.11次。仍有放回抽201次，不把重复抽样算作独立新样本。

新策略名为`class_source_group_balanced`，必须配`class_weighting: none`，避免再次按类别频次加权。旧`shuffle`和`source_group_balanced`行为保留。抽样概率由[PyTorch WeightedRandomSampler](https://docs.pytorch.org/docs/2.11/data.html#torch.utils.data.WeightedRandomSampler)实现；验证和测试保持原始分布，不重采样。

| 项目 | 本轮固定值 |
| --- | --- |
| 训练/验证 | 原v3的201/47张，成员和标签不改 |
| 模型/初始化 | MobileNetV3 Small，原ImageNet初始权重，独立从头开始训练分类头 |
| 骨干/输入 | 骨干及其缓冲区冻结，原224填充和温和训练增强 |
| 优化 | batch16、AdamW、lr0.0003、weight_decay0.0001、seed42 |
| 次数 | 先2轮短跑；通过后仅一个最多30轮、patience8的完整候选 |
| 判定 | 固定argmax，不改阈值 |

仅依据已有验证预测检查阈值时，降低阈值会增加误报，未找到同时保证两类召回改善的依据。本轮没有修改阈值或在旧测试上计算新判定结果。

## 选择与评价边界

当前control最佳验证macro-F1为0.849359，佩戴Recall为66.67%。新候选按验证macro-F1选最佳轮次；只有该轮macro-F1更高（或持平且佩戴Recall更高），并且佩戴Recall不低于control，才替换当前方案。否则保留control，不再追加种子或超参数试验。此规则用于本次实验，不是尚未指定的课程合格门槛。

旧29张和新24张测试都已封存。仅当新候选按上述规则入选，才在另一个冻结、通过来源/重复检查的新保留集上对control和候选各评价一次；未入选时不消耗新的评价集。不会通过重复使用现有测试寻找更好的结果。

另核查[Ultralytics Construction-PPE](https://docs.ultralytics.com/datasets/detect/construction-ppe)作为新来源候选。发布方声明AGPL-3.0，包含护目镜与未佩戴眼部标注；实际图像、裁剪语义、重复和来源关系仍需逐项检查。采用官方ZIP的有界范围读取，至多取100张原图及原标注，不将上游类别直接当作业务标签，不改变现有冻结数据，也不上传原图。其建筑场景不能代替实际实验室域验证。

当前仍缺独立第二标注者、真实实验室图像和课程验收门槛。可以继续完成公开数据与受控实验，不能虚构这些外部证据。
