## 原因与本轮范围

用户在查看剩余任务后要求“进行”，按既定顺序开始真实原始数据核查。本轮读取全部图片/XML，形成问题证据及处理建议，不安装依赖、启动模型、训练或改写原始数据，也不生成正式划分。课程范围仍沿用现有口罩子任务假设，不擅自增加手套或护目镜任务。

旧 `source_check.json` 的 11 份错误只列每图首个失败框，无法说明所有对象和坐标约定，也未检查到后续的重复标注冲突。新增单独的只读核查工具便于完整复现；复用现有坐标转换和 dHash 逻辑，不放宽原程序校验。

## 具体变化与真实发现

1. 脚本逐对象比较两种当前坐标约定，保存类别/含类图片统计、每个原 XML 与图片的哈希、问题对象、完全重复图片与标签差异。输出限制在原目录之外，并拒绝覆盖已有核查目录；前后核对原目录清单和哈希。
2. 生成 30 张定向全图拼图、12 个越界局部、全部 123 个 incorrect 局部和 5 组完全重复对照。首轮局部仅缩小，细小目标难以查看；第二版增加最近邻放大和重复对照，分别保留两轮输出，没有删除或覆盖首轮。
3. 全量检查确认 853 对图片/XML 可读取且尺寸匹配，共 4,072 个对象；with_mask/without_mask/incorrect 分别为 3,232/717/123，含类图片分别为 768/286/97。
4. 11 份标注实际含 12 个右边缘越界框，均为图片宽 400、xmax=401；603 的对象 99、115 是两个独立问题。两种当前坐标约定均有 842 张合法、11 张失败；不把切换坐标配置当作修复。
5. 找到 5 组相同图片字节但框不同的标注：13/737、146/219、410/428、653/775、656/690。各对的类别数量相同，差异主要为框及对象顺序；不是已证明的类别语义冲突。仍需明确每组采用哪个标注版本。
6. 实际查看 30 张全图、12 个越界局部、5 组重复对照，以及 `incorrect_01` 至 `incorrect_04` 的 48 个局部；剩余 75 个 incorrect 局部未逐个查看。记录清楚露鼻/下拉样本、模糊/遮挡疑点和定向抽查的限制。
7. 603 与 518 在视觉对照中呈现相同人群画面变体，dHash 距离 17；阈值 3 无法直接关联。只读预览全部原样本分组得到 839 组、14 个双图片组、最大组 2，没有生成数据划分。记录补充画面分组的必要性。
8. 使用 computer-use 技能，通过已连接 Edge 实际读取 [Kaggle 发布页](https://www.kaggle.com/datasets/andrewmvd/face-mask-detection)：当前版本 1、CC0 标识与 Make ML 归属。网页工具此前只能得到空正文，元数据 API 也未返回有效页面；不将失败读取记为核对成功。原归属链接 [Make ML](https://makeml.app/datasets/mask) 本次显示停放域名，未取得端点细则。原下载 URL 未固定版本号，未重新下载或更改历史 `source.json`。
9. 保存可提交的结构化摘要与中文报告；原数据及新拼图仍被 Git 忽略。更新 README、框架说明、数据选择统计和方案当前状态，索引补齐上轮已确认提交。
